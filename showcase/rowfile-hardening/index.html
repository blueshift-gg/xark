Malformed stream hardening

Make bad proof input fail cleanly.

The row stream is a compact input to Xark’s streaming prover. This work hardens its parser against hostile lengths, window indexes, and encoded variable deltas before those bytes reach constraint decoding.

PR #33 · combined branch

Out-of-range window panicked

decode_window(w) indexed the offset table directly. An invalid public API index could panic instead of returning an error. The guard is part of the combined branch submitted as PR #33.

Local branch · parser hardening

Malformed bytes could overflow or mislead

Header lengths and counts were cast or used in unchecked arithmetic. Window offsets were not checked against row data, and delta-encoded variable IDs could overflow. The local branch adds checked reads, bounded offsets, count-vs-file validation, and error returns. These changes are not on PR #33 until the branch push succeeds.

Reproduction standard

Regression tests cover oversized fingerprint and pool lengths, overflowing LEB128, impossible row/window counts, invalid and overlapping window offsets, variable-delta overflow, duplicate variable IDs, and noncanonical visibility flags. Sparse variable IDs also have a positive compatibility test. They are in crates/ir/src/r1cs_stream.rs.

The branch also has a standalone CUDA kernel test for the 11-bit MSM scalar-window decomposition in crates/groth16/cuda/. It is not wired into the prover yet.

Verification status

The Rust tests have not reached compilation. Cargo cannot resolve the workspace dependency ark-bn254 because crates.io DNS is unavailable. This Mac also has no nvcc or CUDA device, so the new kernel test has not run here.

Formatting, whitespace checks, and dependency-free Cargo metadata pass. The CUDA test command is make -C crates/groth16/cuda test; run it on a CUDA host before treating the kernel as verified. The kernel is not a GPU proving backend.
